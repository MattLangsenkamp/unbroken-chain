# Kubernetes / Helm Conventions

This project uses a **Helm umbrella chart** (`umbrella/`) with `file://` dependencies on per-service charts co-located with their service code. A single `values.yaml` drives all configuration — no per-environment overlays.

## Key Conventions

- **One Helm chart per service**, living at `<service>/k8s/` alongside the Scala source
- **Umbrella chart** at `umbrella/` owns all platform-level resources: databases, message queues, observability, secrets
- **Operators are never bundled** as Helm chart dependencies — they are installed exclusively by `bin/deploy-local.sh` via `helm upgrade --install`
- **Single `values.yaml`** in `umbrella/` — no overlays, no per-environment files
- **`umbrella/charts/` is gitignored** — always regenerated by `helm dependency update`
- **Credentials** flow through ESO: `local-credentials` Secret (created by deploy script, never committed) → `ClusterSecretStore` → `ExternalSecret` → service-specific Secret → env var in pod
- **`make deploy-app`** runs `bin/deploy-local.sh`, which is idempotent and safe to re-run

## Directory Layout

```
umbrella/
  Chart.yaml          # file:// deps on each service's k8s/ dir
  values.yaml         # single values file for the entire platform
  .helmignore
  templates/
    pre-install-check.yaml   # hook: validates operator CRDs before render
    postgres-cluster.yaml    # CloudNativePG Cluster CR
    databases.yaml           # Database CR per Postgres-backed service
    rabbitmq-cluster.yaml    # RabbitmqCluster CR
    otel-collector.yaml      # grafana/otel-lgtm + OpenTelemetryCollector CR
    eso-secret-store.yaml    # ClusterSecretStore + RBAC
    external-secrets.yaml    # ExternalSecret per credential

<service>/
  k8s/
    Chart.yaml
    values.yaml
    .helmignore
    templates/
      deployment.yaml
      service.yaml
      configmap.yaml
```
